# 我们必须想象西西弗斯是幸福的

## 牢骚
昨天当我拖着疲惫的身子，离开坐了快一天的板凳，去撒尿时，我想起来早上在朋友圈刷到的这句话：“我们必须想象西西弗斯是幸福的。”
我忘了朋友圈的那位配了什么样的图片，想要表达什么，我只觉得现在我就是推石头的西西弗斯，三个小时的时间几乎大多数都卡在找bug
上，痛苦，无奈，不甘，但我只能眼睁睁地看着巨石在接近山顶前不断加重。

临近十一点时，女朋友已经显得疲惫了，我不得不起身，但走之前我选择打开gpt，向他询问我困惑的一切，走在路上时我想这这一切，
把女朋友送回宿舍后，我又立马向gpt询问，当然还有抱怨，我诉说着今晚的失败，然后接受人工智能的安慰。
他向我解释，protege是开放世界假设，比起报错，他会尽可能地让事情成为可能。

比如我设定了pizza hasBase exactly 1 pizzaBase，
然后我创建了一个pizza1实例，即使我没定义他有pizzaBase，protege会默许只是还没收到。

```
推理机会这样想：
“PISSA 类说每个实例应该有一个 hasBase 指向一个 PISSA_Base。
我现在没看到 pisaa_1 的 hasBase 信息，
但那不代表它没有，可能只是我还不知道。
所以我不能说这个世界不一致。”

换句话说：

“没写 ≠ 没有。”
“未知 ≠ 错误。”

这就是 OWL 的世界观。
```
好吧，最后在他的帮助下我还是解决了构建一个简单本体的任务，我心满意足地上床，又想起了关于西西弗斯的假设，
突然觉得一切都无所谓了，或许我是西西弗斯吧，那就请让我在巨石滚落之前，更持久地感受接近幸福的幸福吧。

## 笔记
protege：
本体由类、属性、实例组成
1类：
class创建，也可以直接用tool create
2.属性
包括数据属性和对象属性，对象属性表示实例之间的关系，数据属性表示实例的属性，数据属性有数据类型，对象属性没有数据类型
3.实例

本体有约束，比如我让一个类必须满足一个条件，我就可以写成他subclass of ...

...可以添加属性(hasBase some sth)
我也可以通过equivalent to来定义，比如我让厨房满足 "房间 and hasFurniture some stove"
  。注意:这里不要用exactly，
```aiignore
在 Protégé 里是 开放世界假设，意味着：

“没说不代表没有”
“系统不能假设你没告诉它的东西不存在”。

所以当你写 exactly 1 时，推理机想验证：

“神秘房间是不是恰好只有一个灶台？”

但由于 OWL 不知道“神秘房间还有没有别的家具”，
它不能确定没有第二个家具。
于是——无法推理出它是“厨房”。
```
我添加了一条swrl规则：
房子有房间，房间有家具，则房子有家具。
```
house:房子(?x) ^ house:hasRoom(?x, ?y) ^ house:房间(?y) ^ house:hasFurniture(?y, ?z) ^ house:家具(?z) -> house:房子(?x) ^ house:HAS(?x, ?z) ^ house:家具(?z)
```
